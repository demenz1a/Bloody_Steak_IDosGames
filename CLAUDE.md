# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Проект

**Bloody Steak** — 2D-игра на Unity: симулятор кухни со стелс-убийствами (смесь Overcooked и Party Hard). Игрок на кухне — «Овца» (готовит), в зале — «Волк» (может убивать посетителей, чьи трупы перерабатываются в мясо).

- Unity **6000.3.6f1** (Unity 6), URP 2D, Cinemachine 3, TextMesh Pro, NavMeshPlus (`Assets/NavMeshComponents`, свой asmdef).
- Весь игровой код — в `Assembly-CSharp`, без asmdef. Тестов нет.
- Сборка, запуск и проверка компиляции — только через Unity Editor (или `/unity:unity-cli`). Отдельных команд build/lint/test в репозитории нет.
- Git: в PATH нет, работает через GitHub Desktop (`%LOCALAPPDATA%\GitHubDesktop\app-*\resources\app\git\cmd\git.exe`). Remote: `github.com/demenz1a/Bloody_Steak_IDosGames`.

## iDosGames: веб-оболочка и MCP

Игра публикуется на iDosGames внутри веб-оболочки **`IdosWeb/`** (Vite + React, `@idosgames/app-shell`; свой `IdosWeb/IDOS.md` — гайд по ней). Оболочка даёт вход (кошелёк Solana, e-mail, гость), лобби, магазин скинов (модуль `skins`, предметы каталога `Skins` за BloodyCoin — криптовалюта `Main`; в DEV-тайтле цена в Coins для тестов), лидерборд и профиль; Unity-билд — это модуль `IdosWeb/src/modules/bloody-steak`, который грузит `public/unity/Build` как EngineScene. Цвета всего iDos-интерфейса — только в `IdosWeb/src/ui.config.ts` (красный/чёрный/белый/серый из игры).

- Мост игра ↔ оболочка: `Assets/Scripts/Platform/IdosBridge.cs` + `Assets/Plugins/WebGL/IdosBridge.jslib`. Unity вызывает `window.BloodySteakHost.submitScore(score)` (итог смены → лидерборд `best_score`, BestScore). Оболочка ставит игру на паузу через `SendMessage("IdosBridge", "OnHostSuspend"/"OnHostResume")`. Объект `IdosBridge` создаётся сам (`RuntimeInitializeOnLoadMethod`), в сцену его не кладут.
- Сборка для публикации: Unity `WebGLBuild.Build` → `cd IdosWeb; npm run build` (скрипт копирует `Builds/WebGL/Build` в `public/unity/Build`) → zip содержимого `IdosWeb/dist` → загрузка в тайтл. `npm run typecheck` — проверка типов.
- В `.mcp.json` подключён сервер `idosgames-code` (`npx -y @idosgames/mcp`) — реестр кода TS SDK: каркас хоста, модули каталога (`get_module`), скиллы (`get_skill`). Модули каталога кладутся в `IdosWeb/src/modules/<id>/` без правок.

Живую конфигурацию тайтла (`get_*`/`save_*`), генерацию ассетов (`generate_*`, платно) и загрузку билда (`begin_build_upload` → `curl -T` → `finish_build_upload`, только веб-билд с `index.html` в корне zip, т.е. Unity WebGL) даёт отдельный HTTP-сервер iDosGames Title-configuration. `save_*` и `deploy=true` меняют живой тайтл, перед ними нужно подтверждение пользователя.

Тайтл игры: **Bloody Steak**, TitleID `FQFGQZJE` (песочница `FQFGQZJE-DEV`). Веб-билд собирается `Assets/Scripts/Editor/WebGLBuild.cs` (меню **Bloody Steak/Build WebGL** или `Unity.exe -batchmode -quit -projectPath . -buildTarget WebGL -executeMethod WebGLBuild.Build`, редактор должен быть закрыт) в `Builds/WebGL`. Скрипт на время сборки включает Gzip + Decompression Fallback, чтобы билд не зависел от заголовков `Content-Encoding` на хостинге. Страница — свой шаблон `Assets/WebGLTemplates/BloodySteak` (канвас вписан в iframe с сохранением пропорций 960×600, без подвала Unity).

## Старый и новый код

Проект в процессе переписывания:
- **Актуальный код:** `Assets/Scripts/` (корень, `Player/`, `NPCAndOrder/`). Актуальная сцена: `Assets/Scenes/GameScene.unity`.
- **Устаревший код:** `Assets/Scripts/OldScripts/` (все классы с префиксом `Old*`) и сцены в `Assets/Scenes/OldScenes/`. Не расширяй и не используй их в новом коде. В Build Settings включены только `Assets/Scenes/MainMenu.unity` (обновлено под новую версию) и `GameScene`, старые сцены выключены.

## Архитектура (актуальный код)

**Взаимодействие.** Всё, с чем игрок взаимодействует по Space, реализует `IInteractable` (`CanInteract` / `Interact`). `PlayerInteractor` каждый кадр делает `OverlapCircleAll` перед игроком по `FacingDirection`, отбирает объекты с `CanInteract == true` и выбирает ближайший. Подсветка (`InteractionHighlightView` + шейдер `Assets/SpriteOutline.shader` через MaterialPropertyBlock) поэтому всегда соответствует реальной доступности действия. Вся логика доступности (состояние объекта, что в руках, форма игрока) живёт в `CanInteract`. `Interact` вызывается только после `true` и не перепроверяет условия.

**Предметы и перенос.** `CarriableItem` → `Product`. Предметы не имеют физики, они перепривязываются между `HoldPoint` (руки игрока в `PlayerInventory`, слоты `MeatTable`, точка `CookingStation`). Один и тот же экземпляр `Product` живёт от сырого мяса до блюда: станция вызывает `SetType(ProductType)`, а продукт сам меняет спрайт. Мясо создаётся только в `MeatTable` и уничтожается только в `TrashBin` или при выдаче заказа.

**Готовка.** Гриль, шампуры и мясорубка — один компонент `CookingStation` с разным массивом `CookingStage[]` в инспекторе. Новую станцию обычно настраивают данными, а не новым скриптом. Фазы: Empty → Cooking → ReadyToServe → Burnt. Пока станция пустая, в её `holdPoint` видна полупрозрачная проекция блюда (первая servable-стадия); спрайт берётся из `Product.GetSprite` префаба мяса (`previewSource` или `MeatTable.RawMeatPrefab`), объект `FoodPreview` создаётся в рантайме.

**Формы игрока.** `PlayerFormController` (Sheep/Wolf) переключают триггеры `FormZone`: на кухне Sheep, в зале Wolf, в буферной кладовке зоны нет. Подписчики события `OnFormChanged`: `CameraFormSwitcher` (приоритеты Cinemachine-камер) и `OrderManager`. Форма влияет на правила: в форме Wolf таймеры заказов идут медленнее (`wolfTimeScale`), убивать можно только в форме Wolf (заказы создаются в любой форме, как только у стойки есть свободный слот), с трупом в руках нельзя войти на кухню.

**Посетители и заказы** (`NPCAndOrder/`):
- `NpcSpawner` спавнит клиента, только если удалось зарезервировать точку заказа (`PointGroup`/`ReservablePoint`). Клиенты появляются снаружи здания, поэтому колокольчик звенит не при спауне, а когда клиент подходит к `doorPoint` (точка у входной двери в инспекторе спавнера, `NpcCustomer.RingDoorBellAt`). Блюда выбираются так, что следующее никогда не совпадает с предыдущим (`_lastDish`, и внутри заказа, и между клиентами).
- Живой `NpcCustomer` держит `Rigidbody2D` в Kinematic: его двигает только агент, а коллайдер на ногах ниже точки пути цеплялся за стены и Dynamic-тело застревало. Не возвращай Dynamic.
- `NpcCustomer` — машина состояний (`NpcState`) на `NavMeshAgent`. Взаимный обход агентов намеренно выключен (`avoidOtherCustomers`): с ним клиенты толпились во входе и у точек заказа. Не включай его обратно без решения этой проблемы. NPC не создаёт `Order` сам: он вызывает `OrderManager.RequestOrder` и ждёт коллбэк `OnOrderCreated`.
- `OrderManager` — единственный источник правды по заказам. Он хранит очередь ожидающих (`_pendingCustomers`) отдельно от активных заказов (не больше `maxActiveOrders`).
- Заказ хранит `DishFamily`, а не `ProductType`. Сопоставление — в `ProductFamily`. Неверное блюдо вызывает штраф по времени, а не провал заказа. Провал по таймеру увеличивает `MistakeCount`, при `maxMistakes` срабатывает `OnGameOver`.
- `NpcCustomer` — один `IInteractable` на три действия: выдать блюдо, убить, подобрать труп. Цвет обводки выставляется в `CanInteract`.

**Убийство и трупы.** Труп — это тот же `NpcCustomer` в состоянии `Dead`, а не `CarriableItem`. При убийстве агент отключается, а `Rigidbody2D` переводится в Kinematic: иначе тело не следует за родителем. Подобрать труп можно только после того, как доиграла анимация смерти (состояние `deadStateName` в аниматоре, страховка — `corpsePickupMaxDelay`). Подобранный труп становится ребёнком `corpseHoldPoint` в `PlayerCorpseState`. Пока игрок несёт труп, `PlayerInventory` не берёт предметы. `MeatGrinderMachine` уничтожает труп и пополняет `MeatTable`.

**Паника.** `PanicManager` — синглтон (`Instance`). Значение шкалы не хранится, а каждый кадр вычисляется из состояния: если кто-то паникует, шкала равна 1, иначе берётся максимальный прогресс экспозиции. Паника возникает двумя путями: `NpcPanicZone` копит время, пока рядом игрок с трупом, а `PanicManager.ScanForWitnesses` при убийстве мгновенно пугает свидетелей в радиусе (слой `panicZoneMask`). Паникующий NPC отменяет свой заказ без штрафа и бежит к выходу с ускорением ×`panicSpeedMultiplier` (скорость и разгон агента, по умолчанию 2.6 — быстрее игрока). Любой паникующий клиент — и свидетель убийства (`PanicSeverity.WitnessedKill`), и увидевший труп в руках (`Normal`) — поднимает тревогу: если добежит до выхода, `NpcCustomer.EscapeRestaurant` заканчивает игру (`GameOverReason.WitnessEscaped`). Шанс игрока — убить его по дороге. Убитый паникующий снимается с учёта в `PanicManager`, иначе шкала и музыка паники остались бы навсегда. Полиции и пса в новом коде нет.

**Рубильник** (`LightSwitch`, объект `LightSwtich` в сцене). Станция-`IInteractable`: по Space выключает свет на `blackoutDuration` (5 с), после убийства в темноте — только на `afterKillDuration` (1 с). Состояние статическое: `LightSwitch.LightsOut` и событие `LightsChanged`. В темноте нет свидетелей (`PanicManager.ScanForWitnesses`), не копится экспозиция трупа (`NpcPanicZone`), музыка глушится громкостью, а экран затемняет `BlackoutOverlayUI` (первый ребёнок GameUICanvas, под HUD). Перезарядка (`cooldown`) показывается копией радиального таймера станции над рубильником. Настройка: **Bloody Steak/Setup Light Switch** (`Editor/LightSwitchSetup.cs`).

**Геймовер** (`GameOver/`). `GameOverManager` — синглтон и единственный источник правды по состоянию «игра окончена». Это состояние внутри GameScene, а не отдельная сцена. Любая система заканчивает игру через `TriggerGameOver(GameOverReason)`. Сейчас его вызывают `OrderManager.OnGameOver` (кончились попытки, см. `RemainingAttempts`/`OnAttemptsChanged`) и `NpcCustomer.EscapeRestaurant()` (сбежал свидетель). Менеджер глушит музыку, отключает управление и ставит `Time.timeScale = 0`, поэтому `GameOverUI` анимирует всё на unscaled time. Экран собирается в сцене пунктом меню **Bloody Steak/Setup Game Over** (`Assets/Scripts/Editor/GameOverSetup.cs`).

**Смена и победа.** `MatchTimer` (`GameOver/`) отсчитывает смену (`matchDuration`, 300 с). Если игрок дожил, `GameOverManager.TriggerVictory()` → событие `OnVictory` → `VictoryUI` (затемнение вместо крови, разбивка очков). `IsGameOver` значит «игра окончена» в обоих исходах, `IsVictory` различает их. Экран и HUD собираются пунктом меню **Bloody Steak/Setup Victory & Economy** (`Editor/VictorySetup.cs`, есть batch-вход `VictorySetup.SetupGameSceneBatch`).

**Деньги и очки** (`Economy/`). `MoneyManager` начисляет случайную сумму за выполненный заказ (`DifficultyManager.NextOrderReward`, диапазон растёт со сложностью), за провал ничего не снимает; тратить пока нечем. `ScoreManager` даёт очки за заказы и убийства (`NpcCustomer.Killed` — статическое событие; убийство паникующего ×`panicKillMultiplier`). При победе остаток денег (`MoneyManager.TakeAll`) конвертируется в очки; итог в обоих исходах уходит в `IdosBridge.SubmitScore`. `NpcCustomer` вызывает `Killed` до скана свидетелей, чтобы очки за убийство начислялись раньше, чем появятся новые паникующие.

**Сложность** (`Difficulty/`). `DifficultyManager` хранит сложность 0..1: при назначенном `MatchTimer` она растёт вместе с таймером и достигает максимума к концу смены, иначе — до `timeToMaxDifficulty`, по кривой `difficultyCurve`. Каждый параметр задаётся парой `DifficultyRange` (easy/hard). Значения читаются в момент создания: `OrderManager` берёт время заказа, `NpcSpawner` — интервал спауна, шанс двойного заказа и время еды/туалета, которые передаёт в `NpcCustomer.SetStayDurations`. Уже созданные заказы и клиенты на лету не меняются. Без назначенного `DifficultyManager` системы используют свои значения из инспектора. Подключается пунктом меню **Bloody Steak/Setup Difficulty**.

**Скины** (`Skins/`). Моделька игрока (префаб `Assets/Prefabs/Test 1.prefab`) собрана из частей с базовыми спрайтами в `Assets/Sprites/PlayerNew` (холст 1812×2595, у каждой части свой спрайт; голова и тело повара меняются анимацией смены формы). Скин — `PlayerSkin` (таблица «базовый спрайт → спрайт скина» плюс `chefSwaps` только для формы повара). `PlayerSkinApplier` на корне префаба подменяет спрайты в `LateUpdate`, после аниматора, поэтому анимации не трогаются. Форму повара он определяет по тому, что сейчас показывает тело (`chefMarkers`). Со скином голова рисуется поверх всех частей, а в форме повара `Chest` и руки сдвигаются поверх анимации на `PlayerSkin.chefChestOffset` / `chefLeftArmOffset` / `chefRightArmOffset`: тело и руки повара в скинах нарисованы на месте обычных, а анимации повара ставят их под базовое тело повара (другой прямоугольник спрайта, руки подняты). Сдвиги возвращают взаимное расположение формы волка. Выбранный скин (`PlayerSkinSelection`, id) присылает оболочка iDos через `IdosBridge.OnHostSetSkin`. Новый скин: PNG частей на том же холсте с именами `head, chest, chef_head, chef_chest, arm_left, arm_right, chef_arm_left, chef_arm_right, legs, feet, pelvis, tail` кладутся в `Assets/Sprites/Skins/<Name>/`, затем **Bloody Steak/Import Player Skin**. Импортёр копирует настройки базовых текстур, режет спрайты по их прямоугольникам с сохранением pivot и добавляет скин в `Assets/Resources/PlayerSkinCatalog.asset`. Затем нужно добавить предмет и слот магазина в тайтле, превью в `IdosWeb/public/skins/` и строку в `IdosWeb/src/shared/skins.ts`.

**Звуки** (`Audio/`). `SoundManager` — синглтон на Managers, единственная точка воспроизведения. Каждый звук — `SoundId`, клипы задаются в инспекторе: строка на каждый id появляется сама, пустой клип даёт тишину. Системы зовут статические `SoundManager.Play / StartLoop(id, owner) / StopLoop(owner)`. События заказов (`OrderManager`), конца игры (`GameOverManager`), тиканье таймера (`MatchTimer`, последние `clockTickSeconds`) и «игрока заметили» (`PanicManager.OnPanicStarted`) менеджер слушает сам. Петли станций: `CookingStation.cookingLoop` (у `Mincer` — Grinder) и `MeatGrinderMachine`. Шаги — `FootstepSounds` на префабе игрока, по таймеру. Кинжал и падение — Animation Events `PlaySound("KillRaise"/"BodyFall")` в `WolfKillerKill` и `NPCMaleDead`, приёмник `AnimationSoundEvents` висит на объектах с Animator. Настройка: **Bloody Steak/Setup Sounds** (`Editor/SoundSetup.cs`). Клипы лежат в `Assets/Audio/<SoundId>/` (все CC0, источники в `Assets/Audio/Licenses/CREDITS.txt`). **Bloody Steak/Assign Sounds From Folders** назначает в `SoundManager` всё, что лежит в этих папках: чтобы заменить звук, достаточно поменять файлы в папке.

**Музыка.** `MusicManager` (на Managers, меню **Bloody Steak/Setup Music**) — три слоя одной композиции из `Assets/Audio/Music`: повар → волк → паника (`PanicManager.IsPanicActive` перебивает форму). Все слои играют одновременно, переключение — кроссфейд громкости. Слой 1 зациклен и задаёт время; слои 2 и 3 перезапускаются по `AudioSettings.dspTime` (`PlayScheduled`, по два источника на слой) ровно на его стыке, поэтому не расходятся, даже если длины mp3 отличаются на доли секунды. Не заменяй это на `loop = true` у всех слоёв: так слои постепенно разъедутся.

**Движение.** `PlayerMovement` двигает игрока через `Rigidbody2D.MovePosition`, ввод через legacy `Input` (Active Input Handling = Both). Он ничего не знает о других системах. Блокировку движения на время анимаций включают Animation Events через `MovementLockEvents`.

## Соглашения

- Комментарии и XML-доки пишутся на русском и часто ссылаются на пункты ТЗ («п. 9.5», «п. 13.4»). Сохраняй этот стиль.
- Связи между компонентами задаются через `[SerializeField] private`-поля в инспекторе, а события — через C# `event Action<...>`. Подписка в `OnEnable`, отписка в `OnDisable`.
- UI-компоненты (`*UI`, `*View`) только отображают состояние и не содержат игровой логики.
- **Кодировка:** все `.cs` без BOM, но часть файлов (`IInteractable.cs`, `ItemTypes.cs`, `ItemSlotView.cs`, `CameraFormSwitcher.cs`, `Player/PlayerForm.cs`, `Player/PlayerFormController.cs`) сохранена в Windows-1251, остальные в UTF-8. Перед правкой русских комментариев проверяй кодировку файла и не смешивай кодировки в одном файле.
